# 主世界昼夜流动性能修复（2026-09-23）

## 结论

时间流动原来每帧调用全量设置应用，包括 VSync、阴影图/过滤配置、相机效果、天气设置、水材质方案、光源分配及资源复制。拆分后每帧只更新受时间影响的值；完整设置仍在初始化/用户更改时应用。平面反射 Environment 改为复用，天空资源继续共享，云 Profile 只在设置变化时复制。

没有改变阴影贴图分辨率、反射分辨率、Sky 处理模式或日月更新频率。此对比确认了全量设置路径的组合开销，没有逐个剖析 VSync、渲染质量 setter 的贡献，不将全部成本归因于某一个 API。

## 短时诊断

- Godot 4.7 stable；Forward+ / D3D12；RTX 3060 Laptop GPU；1280×720；水平视距 48。
- 主世界实际代码，临时世界/配置；固定相机 `(12,42,16)` 看向 `(0,31,0)`。该位置靠近地表下方、可见几何较少，适合隔离设置路径，不代表正常地面游玩负载。
- 时间起点 12 点，一日 1200 秒；不限帧、VSync 关；晴天；平面反射强制每帧更新并关闭离屏暂停。
- 每个反射模式采用 暂停→流动→流动→暂停；各档预热 1 秒、采样 3 秒。使用实际帧间隔的中位数/P95，不使用最大 FPS；每格列出两轮范围。

| 水反射 | 时钟 | 修复前中位帧耗时 ms | 修复后中位帧耗时 ms | 修复前 P95 ms | 修复后 P95 ms |

开启平面反射与时间流动时，旧版每个采样段更换 Environment 111–112 次；新版全部为 0。正常权限再次验证得到天空反射流动 2.343–2.411 ms、平面反射流动 3.218–3.312 ms，回归检查失败数 0。

这属于故障修复的短时诊断，不是 1080p/256 视距基准，不能外推为主世界长期 FPS 保证。笔记本温度和后台负载未受严格控制。
