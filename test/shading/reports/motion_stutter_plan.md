# 移动与转向卡顿自动诊断

入口：`test/shading/scenes/motion_stutter.tscn`。在 Godot 中打开此场景按 F6；默认完成后退出游戏。根节点可调视距、每档采样秒数、重复轮数及退出行为。

测试使用真实 main 场景、原生地形和全部默认光影配置；独立临时存档，不读取或覆盖用户主世界/光影偏好。固定正午、晴天，关闭日夜流动、VSync 和限帧。停用测试世界的自动保存，排除保存尖峰。生成、流式加载、网格/碰撞和其他光影仍运行。

## 动作与对照

| 动作 | 相机/观察器行为 | 主要目的 |
| --- | --- | --- |
| static | 玩家与相机均不动 | 静止基线 |
| yaw | 相机坐标固定，仅以 90°/s 旋转 | 可见物体、阴影、反射随朝向变化 |
| orbit_center | 半径 4m 绕玩家旋转，中心位于区段内部 | 第三人称轨道运动，不跨光照窗口边界 |
| orbit_boundary | 同样轨道，中心放在 x=16 边界 | 验证仅转视角导致光照窗口反复切换 |
| move | 玩家、观察器和相机以 8m/s 水平前进 | 区段加载、光场移动窗口和结果提交 |

每个动作包含 normal（正常光照更新）和 frozen（冻结光场调度）两档。冻结档在测试驱动中抑制窗口失效，并暂时断开区段加载/卸载对光场的失效回调，保留旧纹理；阶段结束恢复连接。其他光影及地形加载继续运行；画面可能使用过时光照，只用于归因，正式游戏不提供此开关。阶段前等待光场稳定至少 1.5 秒，最长 90 秒，超时输出失败报告。每阶段起始视角另预热 0.5 秒。

运动通过确定路径驱动真实主世界相机和玩家位置，不经过鼠标事件、CharacterMotor 或 SpringArm 碰撞；它隔离运动造成的加载/渲染成本，不能验证输入设备、相机碰撞和物理插值。主线程逐帧事件关联也不能替代 GPU profiler。

默认 64m 视距，每档 8 秒，共 10 档；包含初始化与稳定等待一般约 2–4 分钟。建议正式对照使用 2 轮：第二轮反转 normal/frozen 顺序，以减轻缓存和温度顺序偏差。不是严格热平衡基准，不自动关闭用户的其他应用。

## 启动命令

```powershell
& 'F:/Godot_v4.7-stable_win64.exe/Godot_v4.7-stable_win64_console.exe' --path . --log-file tmp/motion-stutter-engine.log --rendering-method forward_plus --rendering-driver d3d12 --resolution 1920x1080 res://test/shading/scenes/motion_stutter.tscn -- --seconds=8 --distance=64 --rounds=2
```

测试时保持游戏窗口前台；任何失焦帧会使该次报告标记为不满足性能对照条件。不要与其他游戏/性能测试同时运行。

## 输出

每次运行创建 `tmp/motion-stutter/<时间戳>/`：

- `report.md`：各档 FPS、1% Low、P99、最长帧、慢帧次数及光照事件关联。
- `frames.csv`：逐帧时间、快照/发布/天气图 CPU 耗时、数据区段加载/卸载次数、相机位置与焦点。
- `results.json`：引擎、GPU、分辨率、光影配置、阶段汇总及精确事件时间戳。
- `world/`：本次临时世界。

主线程的 snapshot 与 publish 时间由正式 shading 的 opt-in 信号提供，默认关闭；关闭时不读取时钟或建立诊断记录。publish 包含天气表面图更新时间，不能将两者相加。纹理提交的 CPU 计时不等同于 GPU 完成上传的时间。区段 loaded/unloaded 是数据驻留事件，不是网格提交耗时，不能冒充后者。

1% Low = 最慢 ceil(帧数×1%) 帧的平均耗时取倒数。大于 16.67ms 的慢帧若在同一采样区间发生快照/发布，记为关联帧，不自动判定因果；渲染线程/GPU 的影响可能延后。开始或结束阶段的跨阶段帧不纳入统计。

优先看 boundary-normal 与 boundary-frozen 的差别；若冻结显著改善且慢帧伴随快照/发布，再细分光照路径。若 yaw-frozen 仍卡，进一步检查渲染、管线编译或输入链路；本测试不自动更改阴影/反射画质来掩盖问题。
