# 1080p 光影设置成本测试方案（最长 1 小时）

状态：2026-09-18 首轮耗时 56 分 8 秒，后续授权的附加档位补测耗时 8 分 4 秒，现已覆盖 98 个可评级设置、166/166 对照用例，累计 18 组复测；结果与温控限制见 [本轮结果](lighting_performance_results_20260918.md)。本方案针对独立 64³ 光照样板，不能代表正式流式世界的 256 视距性能。

## 目标与交付

测量当前每个效果／参数在明确场景下的增量成本，输出设置名称、参考值、测试值、FPS 变化、毫秒增量、影响等级、波动与覆盖状态。最大 FPS 不用于评级。用户人工判断作为对照列保留，不用它生成测量值。

入口 `test/shader/runners/run_lighting_suite.py` 默认只显示规划统计，不启动 Godot 或遥测，也不写结果目录。真正执行必须显式提供 `--run`。报告可以从已有原始数据单独重建。

```powershell
# 安全预览：只生成内存中的计划并打印数量
python test/shader/runners/run_lighting_suite.py

# 短时实际验证：6 个用例强制 ABBA + BAAB，另含两个短组合
python test/shader/runners/run_lighting_suite.py --run --smoke

# 指定当前用例 ID 补测：保留预热与 ABBA/必要 BAAB，省略持续组合
python test/shader/runners/run_lighting_suite.py --run --cases c126 c127

# 等用户另行授权后使用：真实运行，目标约 50–60 分钟
python test/shader/runners/run_lighting_suite.py --run

# 可选：明确指定 Godot 安装与 NVIDIA GPU 索引
python test/shader/runners/run_lighting_suite.py --run --godot "F:/Godot_v4.7-stable_win64.exe/Godot_v4.7-stable_win64.exe" --gpu 0

# 仅重建已有报告，不启动测试
python test/shader/runners/run_lighting_suite.py --report-only tmp/lighting-cost-YYYYMMDD-HHMMSS
```

需要 Python 3.10+ 标准库与项目当前 Godot 4.7 stable、已导入的嵌套工程和 Voxel Tools 二进制。入口不会自动导入、下载引擎或安装分析工具。若缺少依赖，停止并保留错误记录。测试前关闭该嵌套工程的编辑器，不同时执行其他性能任务。

`--cases` 仅选择当前矩阵中的 ID，不改变该用例配置；不存在的 ID 直接报错，不与 `--smoke` 或 `--report-only` 混用。选定用例的首轮必须全部产生完整配对，否则本次运行判为失败。结果写入新目录，不跨运行合并原始帧或复测差值；结合旧结果评价时需标明来源和热状态。补测保留 180 秒预热、1.5 秒稳定、3 秒采样；按用例数缩小截止预算，并省略已完成的持续组合。默认不加 `--run` 仍只预览。

## 时间预算与顺序

| 时间节点（从驱动启动计算） | 内容 |
|---|---|
| 启动及初始收敛 | 创建一次样板，等待传播／网格／纹理发布；收敛超时不假装开始测量 |
| 随后 180 秒 | 固定水面反射、阴影、云的代表负载预热，不保存性能帧；这是预热，不保证热平衡 |
| 第 49 分钟之前 | 主要方案 → 各设置首次有效探测 → 额外数值扫描。每组四个状态 A–B–B–A |
| 第 49–54 分钟 | 对基线漂移、差值反向或不一致的组追加 B–A–A–B；若前阶段提前结束，复测也可提前开始 |
| 第 54–58 分钟内 | 剩余时间下进行不限帧／120 FPS 限帧的候选组合，各 60 秒；已超预算则跳过 |
| 第 58 分钟 | 驱动停止采样，落盘已完成内容 |
| 第 59 分钟 | Python 看门狗终止自己启动且未退出的 Godot 进程，防止场景挂起后超时 |
| 预留最后约 1 分钟 | 停止遥测、扫描错误并生成 Markdown／JSON 报告 |

当前规划 101 个导出设置、166 组对照（最终以入口打印为准）。每个状态稳定至少 1.5 秒、采样 3 秒；四段约 18 秒一组。全矩阵理想首遍约 53 分钟，额外几何更新、I/O 和异常会增加时间，因此优先覆盖每个设置的首个探测，不能承诺 1 小时内完成所有附加扫描。

每组启动前检查窗口焦点与尺寸；失焦或被改为非 1920×1080 时停止并记录。用户应保持测试窗口前台。强制中止发生在正在采样的段时，该段不用于配对结论；之前完成的段仍可恢复。硬预算针对测试进程；极端磁盘或系统阻塞可能使报告落盘超过预留时间，程序不会为补齐用例重新运行。

## 环境与测量隔离

- 1920×1080 主窗口直接渲染，3D scale=1；不使用额外的全屏 TextureRect／SubViewport 展示层。
- Forward+／D3D12；不限帧、VSync 关闭；只有最后一个组合例外设为 120 FPS。
- 保持插电、电源／风扇模式、外部程序和驱动设置一致。脚本不锁频、不修改系统电源策略。
- 控件、HUD 和输入捕获关闭；测量期间不写 settings.cfg、不截图、不导出逐帧文本。
- 测试专属输出在 checkout 的 tmp 下新目录，禁止覆盖旧结果。不读取用户真实设置文件。
- 每段将逐帧数据暂存在内存，采样结束后写 CSV 并追加／flush 事件记录；切换、磁盘写入不混入稳态帧时间。
- 重置动画、水波、风、云位移时钟和相机起点；动态用例走相同墙钟轨迹。不同 FPS 仍有离散采样差异，不能声称逐帧完全相同。
- 网格和光传播必须收敛后进入稳态采样；放置／挖掘用例显式在采样起点触发操作。
- CPU 驱动调用样板原 `_process` 更新，计时其墙钟耗时；只以 `benchmark_mode` 抑制 HUD 和设置面板同步，普通样板行为不变。

参考配置只对本次基准生效：最低环境光 0.015、阴影偏移 0.06、法线偏移 2.0。普通样板的默认法线偏移仍为 1.7，本任务不修改人工默认值。

## 指标与边界

| 指标 | 获取方式 | 解释 |
|---|---|---|
| 平均 FPS | 采样帧数 ÷ 逐帧间隔总时长 | 不取瞬时最大值，也不平均每帧倒数 |
| 整帧中位数／P95／P99 | 相邻 frame_post_draw 的单调时钟间隔 | 应用完成帧节奏，不是物理显示扫描时间 |
| 超 8.33／11.11／16.67ms 比例 | 同一逐帧数据计算 | 对应 120／90／60 FPS 帧预算 |
| 样板更新 CPU | 样板 `_process` 前后墙钟差 | 只包含驱动调用的更新工作，不是整个 CPU 利用率 |
| 渲染 CPU | Godot 主／反射视口 render CPU + frame setup | 单列；不与整帧时间简单相加 |
| GPU 主视口 | RenderingServer 视口测量 | 0 或缺失视为无法可靠测量，不能报零成本 |
| GPU 反射视口 | 捕捉发生时记录反射视口 GPU 时间 | 未更新帧不重复计入旧值；保留 capture 标记和频率 |
| GPU 总估计 | 主视口 + 按捕捉频率加权的反射成本 | 使用段均值体现限频收益；不是 GPU Busy，也不是绝对负载百分比 |
| 绘制／图元／显存 | Performance 监视器 | 保存原始值到段汇总，用于解释成本变化 |
| 温度／频率／功耗／限制原因 | 独立 nvidia-smi 进程每秒记录一次 | 不启动覆盖层，不逐帧创建进程；不含 CPU 温度／有效频率 |

Godot 的 GPU 计时是异步返回的“最近一次”视口时间。限频捕捉的调度帧与计时回传可能不同步，本实现将其按捕捉次数计入并明确标为估计；适合段级对照，不用于判定某一个尖峰帧的 GPU 根因。若需精确归因，后续另行接入 PresentMon／时间戳查询，不把估计伪装为精确 GPU Busy。

官方接口依据：[Godot RenderingServer](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html)、[NVIDIA SMI](https://docs.nvidia.com/deploy/nvidia-smi/)。GPU 限帧后可能降低频率，计时因此变大；本测试不按频率比例“校正”所有结果。

遥测不存在、查询字段不支持或返回 N/A 时，保留诊断日志并在报告中标为缺失；不为继续采集而猜测驱动接口。多显卡机器必须保证 `--gpu` 与实际渲染 GPU 匹配，报告同时记录两者。CPU 温度和 CPU 有效频率未采集，因此仅凭 GPU 温度不能排除 CPU 热／功耗影响。

主要方案包括 AO／雾／日月光／阴影开关、FXAA／TAA、两种水色、SSR／平面反射、云与云影、五种局部照明方案。参数父项在矩阵中明确开启，例如 SSR 参数只在 SSR 下测试，软滤波只在软阴影下测试，最低环境光颜色测试时补光非零。

关键扫描点：

- 阴影贴图 1024／2048／4096／8192，距离 32／96／192／256，所有滤波采样选项，硬／软及模糊半径 0／1／2／4。
- SSR 步数 8／16／32／64／128，细化 0／3／5／8；其他参数以默认和一个代表极值对照。
- 平面反射宽高倍率 0.25／0.5／0.75／1，更新 15／30／60／每帧；包含植被、云、雾、反射 FXAA 分别对照。
- 每种局部照明在 1／8／16／32 灯下比较；混合点灯上限 0／4／8／16／32，阴影预算 0／2／4／8／16。预算扫描使用 32 个可选光源，扫描阴影预算时点光源上限固定 32，避免参数被其他上限截断。
- 自发光倍率 0／0.5／1.5／4／8；主要关闭 Bloom，额外一个 Bloom 组合用于区别附加辉光成本。
- 环境光平滑 0／0.5／1，最低强度 0／0.015／0.05；颜色、曝光、衰减等也进入探测，而非预设零成本。
- 传播预算在固定 128 方块放置／挖掘下比较。记录同步提交和传播／网格／纹理全部完成延迟；采样期未完成记 -1，并明确未完成。

只有 show_fps、max_fps、vsync_enabled 被列为控制策略：前两项中的 HUD 固定关闭，VSync 固定关闭，最大帧数在最后的组合中对照。它们不进入普通效果排行榜。新导出设置若未覆盖，计划生成直接报错，不会静默漏项。

写实体积云已删除，不恢复测试。普通方块云与云影分开测，避免把两个模块的成本混为一项。

## 噪声、热漂移与自动复测

每个 ABBA 得到两对差值；复测 BAAB 再补两对。自动复测触发条件：A 基线中位数漂移超过 5%，两对差值方向相反，或两对差值相差超过 0.15ms。复测有独立截止时间，不为追求显著性无限追加。

报告输出配对差值中位数与最小～最大区间；该区间不是统计 95% 置信区间，两个短片段也不构成强证据。差值跨零或小于 max(0.03ms, 半区间宽度) 时标记“未检出稳定差异”。参考漂移 >5% 或同组 GPU 频率跨度 >5% 时影响等级暂定，记录原始数值但不强行下结论。

脚本不会自动冷却、降档或调整风扇，热漂移组只在预算允许时追加对照。GPU 遥测未取得、CPU 温度未观测、驱动编译残余或动态场景差异均是报告边界。最后各 60 秒的组合只是持续表现抽查，不能声称充分热稳定；因设置本身增加功耗导致的持续变慢仍是实际本机成本。

| 设置名称 | A→B | 场景／灯数 | 基准 FPS | 测试 FPS | ΔFPS／% | Δ整帧 ms及范围 | ΔGPU估计 ms | Δ更新CPU ms | Δ渲染CPU ms | ΔP99 ms | 帧／GPU等级 | 判断 | 人工预判 |
|---|---|---|---:|---:|---|---|---:|---:|---:|---:|---|---|---|
| 由实测生成 | 明确值 | 固定上下文 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 原样保留 |

等级分别对帧成本和 GPU 估计成本计算：极低 <0.10ms；低 0.10–<0.50ms；中 0.50–<1.00ms；高 1.00–<2.50ms；极高 ≥2.50ms。负值标为改善；不显著、频率漂移或缺失计时则标为待定／不支持。P99 增量超过 1ms 另外标记尾帧风险。绝不将每项成本简单相加来预测组合性能。

报告附带逐设置覆盖表、编辑／组合表、主机信息、异常退出状态。未开始或只有一半配对的项目写成待测。对于测量受温度或频率干扰的结果，用户人工预判与实测数值并列，不自动修改默认画质。

输出文件：

- manifest.json：完整参数、场景、优先级、时间预算与人工预判。
- host.json：引擎、Git 状态、驱动启动结果、日志错误、遥测状态。
- events.jsonl：每段开始／完成信息、应用耗时、成对漂移和退出原因。
- 逐段 CSV：帧时间、CPU／GPU、反射捕捉标志、绘制／显存数据。
- telemetry.csv 与 telemetry-status.log：独立硬件遥测及查询错误。
- report.md：用户阅读的分类表格。
- summary.json 与 segments.json：对照结论与段级统计，便于后续整理画质默认值。
