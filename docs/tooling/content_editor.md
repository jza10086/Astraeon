# 专用内容编辑器

## 入口与数据归属

在 Godot 4.7 顶部点击 **内容编辑器**。插件为 `addons/astraeon_content`，复用现有编译器、格式 2 包工程和 `.aebpack`；没有新增容器、世界存档格式或运行后端。打开原版 `game/data/content/authoring/astraeon/pack.tres` 或自己的包工程即可制作。原生 Inspector 仍可用于外部编辑，但需处理双方的文件冲突。

主工作区：顶部包工程工具栏；左侧方块 / 物品 / 流体列表；中间实时预览；右侧材质 / 逻辑数据多级折叠；底部校验和导出结果。侧栏较挤时可拖动分隔线或使用 Godot 自带的专注模式。列表支持名称和 ID 搜索，属性支持中文名称、分组名与原字段名搜索。悬停字段可见字段名及单位，↶ 恢复字段默认值；枚举与开关控制相关字段显隐。

- **方块**：默认表面、六面覆盖及 UV、制作朝向、自发光、独立局部光源、树叶内部面、十阶段裂纹；逻辑为 ID/名称、硬度/工具/恢复时间、碰撞/传播光、显式状态/默认状态及加载策略。
- **物品**：独立工具物品和方块关联物品统一列出。关联物品标注所属方块，可与方块表单双向跳转；始终编辑 BlockAsset.item，保存回同一个方块文件。独立物品维持非方块物品契约，不创建重复方块定义。方块表单可为未配物品的方块建立关联物品。
- **流体**：只编辑现有水体定义；水色、吸收、表面、波纹、反射响应、水下颜色和衰减，以及 ID/名称/碰撞/逻辑透光。不增加流动模拟。
- 法线、ORM、自发光贴图明确标为尚未接入，不能编辑。制作朝向和实例允许朝向分开；表面自发光、局部光源强度和传播光等级分开。没有坐标、当前挖掘进度等实例字段。

## 制作与文件操作

1. 新建包：输入命名空间，选择 `pack.tres` 保存位置；新建方块、物品或水体。方块可同时创建关联物品。
2. 选择图片：从文件系统选择开发者管理的图片，或复用已有图片键。图片不复制到制作资源；同盘保存相对包工程路径，跨盘保存绝对路径。显示缩略图、尺寸、实际路径和缺失状态。刷新图片会重新读源图并更新预览。
3. 包设置管理包名称、命名空间、依赖、图片索引和创造目录分组。字典以每行 `key=value` 输入，点击“应用”提交；不接受重复键。修改命名空间后需同步内容 ID，校验不会自动重命名。
4. 编辑的是私有深拷贝。撤销 / 重做通过工具栏操作，未保存时显示圆点。切换 / 关闭工程提供保存、放弃、取消；编辑器退出通过 EditorPlugin 的未保存提示参与原生流程。文件哈希变化会显示提示，保存时必须明确覆盖或放弃本地后重新加载。
5. 保存全部只写制作文件。每个文件先写临时资源，再替换；最后保存工程索引。**原子替换是逐文件的，不是整个工程多文件事务**。I/O 错误停止保存并保留未保存标记，不自动换路径或重试。
6. 复制必须使用新内容 ID。移出包只解除索引，源文件保留；关联图片被使用时不能移除索引。旧文件路径与新建文件冲突也走外部文件冲突确认，不静默覆盖。
7. 导出先保存、再校验、再调用现有编译器。底部错误可定位相关资源 / 字段。包体独立包含像素载荷，本地 `.receipt.json` 记录源指纹，不随游戏发布。收据写入失败会明确报告“包已写入但收据失败”，不能作为成功导出使用。

源文件共享与包契约见 [内容包](../data/content_packages.md)、[资源规格](../resource_specifications.md)。不支持把 `.aebpack` 反编译回工程。

## 基础预览

仅编译选中资源到项目 `tmp/content/editor/<实例>/preview.aebpack`，复用 C++ 编译器、内容包读取 / 视觉缓存、VoxelMesherBlocky 和生产 ShaderMaterial 绑定。纹理加载就绪后绘制，不另写颜色图集合成器。资源修改停顿 250ms 后合并更新；隐藏主工作区停止调度、绘制和波纹时钟。源码资源类型增加 `@tool`，使同一验证与材质 API 可在编辑器执行。

- 方块：中键拖动旋转、Shift＋中键平移、滚轮或 Ctrl＋中键上下拖动缩放；六面／透视按钮切换方向并重新居中，显式状态切换；显示贴图、裁剪、光泽、自发光、局部照明，并可选择十阶段裂纹。
- 物品：透明棋盘背景显示编译后的图标；无图标使用定义的基础颜色，关联物品同时显示方块。
- 水体：固定水位及浅 / 深池底；复用水面材质和固定天空色，支持暂停波纹。

相机禁用生产着色器保留的第 20 层反射标记，避免误裁剪普通模型。预览只提供常量光照页，不启动正式世界、存档或传播光。固定环境、曝光和灯光不代表正式世界的最终亮度；完整昼夜、天气、SSR、平面反射、水下镜头继续在光影样板检查。单个高分辨率外观离线编译仍可能短暂占用编辑器主线程；本轮不承诺性能指标。

## 实现、设置与 SDK

- `content_session.gd`：文档、文件归属、私有工作副本、撤销历史、冲突检测、保存和编译。
- `content_form.gd`：中文分层字段、条件控件、图片选择 / 缩略图及颜色弹窗边界。
- `content_preview.gd`：选中资源的隔离编译与原生预览。
- `content_editor.gd` / `content_editor.tscn`：工作区、对话框、列表、错误定位和折叠 / 分栏状态。
- `plugin.gd`：唯一宿主及现有正式导出检查。编辑器布局格式 1 保存在 ProjectPaths 指向的 `runtime_data/content_editor.cfg`；不支持的配置明确报错，不写 OS 用户目录。

`python tools/content/build_sdk.py` 从当前脚本、场景、着色器、示例资源与匹配 editor/debug DLL 生成 SDK，包含同一内容编辑器；SDK 采用 Forward+。没有独立维护的资源实现或第二个工具宿主。

验证入口和实机截图见 [专用编辑器测试](../../test/content_editor/README.md)。
