# 多方案地图实验模块

状态：2026-09-17 已按用户指令执行引擎导入、正确性与综合测量。正确性 238 项及异步生命周期 10 项通过；持续移动的网格吞吐尚未达标。具体进程状态、统计和局限见 [本轮测试报告](world_suite_results_20260917.md)，不依据未就绪场景的高 FPS 选择最终方案。

主场景现为独立玩家碰撞测试场，尚未接入本地图实验；实验通过 tests/world/world_benchmark.tscn 独立启动，不依赖 benchmarks/voxelgame 的原生 VoxelBuffer。所有后端采用相同暴露面网格算法、材质和静态三角形碰撞，因此只能比较本实现，不能直接与原生插件的 FPS 相比。

## 已实现方案

以下参数均从 0 开始编号：

| 参数 | 值 |
| --- | --- |
| generator | 0=G1 独立段采样；1=G2 区块列缓存；2=G3 世界坐标对齐稀疏采样插值 |
| backend | 0=DIRECT32；1=DIRECT16；2=PALETTE |
| codec | 0=16 位直接；1=直接+FastLZ；2=直接+Zstandard；3=调色板位打包；4=调色板位打包+FastLZ |
| files | 0=独立段双快照文件；1=区域追加记录+双索引快照 |
| layout | 0=自然布局；1=沿 X 轴周期排列的受控布局 |

G1/G2 要求逐格一致；G3 是质量取舍方案，单独记录高度误差和海陆分类变化。G2 缓存每个工作器独立且有容量上限，不能把所有任务的累计命中数当作单次命中数相加。

地形包含平原、沙漠、山地、海洋。地层使用空气、石头、泥土、草、沙、水六种状态；测试目录由自定义 BlockDefinition Resource 构建，不修改现有 default_block_catalog.tres。水是蓝色不透明方块，无流动、不产生碰撞；没有洞穴、树木、生物和正式玩家控制器。

测试世界 Y∈[-64,192)，海平面 32；这些不是最终游戏世界限制。区块列 16×16、段 16³，沿用负坐标向下取整。圆形加载使用既有整数判定；暴露面算法只需六个面邻居，因此本实现使用六面数据边框，不需要原生基准的斜向邻居边框。

## 模块

- game/world/generation/world_config.gd：Resource 参数与可持久化配置快照。
- game/world/generation/terrain_generator.gd：三生成器策略、四类地形、有限列缓存。
- game/world/persistence/section_codec.gd：五编码、纯色特例、压缩无收益回退、SHA-256 校验。
- game/world/persistence/world_store.gd：世界状态表、磁盘 ID 映射、两种文件组织、索引/句柄缓存与恢复。
- game/world/runtime/world_worker.gd：工作器自己的生成上下文，处理加载、保存、网格任务。
- game/world/runtime/world_runtime.gd：主线程数据所有权、请求代号、内容版本、提交预算、保存与卸载。
- game/world/presentation/terrain_mesher.gd：共用暴露面网格与碰撞三角形生成。
- tests/world/world_data_suite.gd：正确性和数据层测试入口，默认不执行。
- tests/world/world_benchmark.gd/.tscn：图形实验，默认只显示待命提示。
- tools/run_world_suite.py：矩阵、独立进程、超时、Windows 进程内存采集、结果汇总与曲线。

## 数据与保存契约

运行时继续使用 BlockSection 和选定后端。网格工作器接收独立快照，并重建所选后端进行读取；快照与重建耗时计入记录。当前未增加绕过校验的直接字节导入快捷路径。

世界状态表保存稳定方块/状态 key；存档 ID 只追加、不回收。打开世界先构建映射，缺失状态拒绝打开。新增状态表先可靠提交，之后才允许保存引用其新 ID 的段。配置不匹配拒绝打开，生成方案切换需要独立世界或明确迁移；首版不提供自动世界迁移。

已接纳的生成结果首次保存，后续按内容版本保存；全空气段同样保存。使用单段快照语义，没有跨段事务。运行时不会在保存确认前卸载脏段，同段保存串行，后台旧网格/加载结果检查请求代号与内容版本。

文件使用有版本标识、长度边界和 SHA-256 的 Godot Variant 二进制封装。没有启用对象反序列化；这不是 Minecraft NBT/MCA 兼容格式，也不承诺跨任意未来 Godot 版本免迁移。

F1 为每段保留交替的 .0/.1 文件。F2 每个区域覆盖 16×16 水平区块列，追加段记录后 flush，再交替写入校验过的索引快照；每个段的索引保留前一记录位置。索引缓存上限 64 区域，文件句柄缓存上限 16。首版单进程访问，I/O 由互斥锁串行，压缩可在锁外运行。

损坏记录回退前一有效记录并标记 recovered；两份均损坏报告错误。区域索引恢复后无法确认某段是否曾保存时报告错误，不把它当成从未生成。区域追加文件尚无整理器，会保留历史记录；统计磁盘大小时必须同时考虑这个写入放大。flush/双快照并不等价于对所有文件系统提供断电不丢失保证。

## 调度与图形边界

默认两个工作器、64 格水平半径、32 格垂直半径、4096 段驻留上限。已派发任务最多等于工作器数量；未派发请求只保存坐标和时间，不提前复制整段。保存到期、首次生成或需要卸载时优先保存，之后优先派发邻居数据已齐备的可见网格，再调度加载，避免连续移动使网格任务饥饿。

主线程默认 2ms 提交预算，只能在任务之间让出；单个网格或碰撞提交可能超过预算，须由实测反映。网格、碰撞的实际场景提交都在主线程，工作器不修改活动场景树。

测试采用实际图形窗口、固定 1280×720 内容尺寸、禁用 VSync 和 FPS 上限。固定路线按时间推进，不等待生成追上；缺失地形数量、请求到可见延迟和阶段就绪标记必须与 FPS 一起看。初始化最长 240 秒；保存排空最长 240 秒。未完成可见负载、编辑目标未加载或排空超时标记 incomplete，不隐藏高 FPS 背后的空场景。

这里的碰撞验收是构建实际碰撞体；新增玩家模块尚未接入本地图实验，因此尚未验证此地形的行走物理手感。

## 正确性检查

正确性入口已执行下列用例：

- 三后端、G1/G2 内容一致；负坐标与请求顺序；G3 重复生成一致。
- 五编码、多种调色板大小、65535 状态上限、校验失败、ID 重映射。
- F1/F2 × 五编码，保存往返、全空气段重新打开、编辑后快照隔离。
- 人为损坏最新记录后恢复前一版本；真实注册表新增导致运行 ID 重排；缺失定义拒绝覆盖。
- G3 相对 G1 的高度误差、海陆变化比例。

`tests/world/test_runtime_lifecycle.gd` 另覆盖保存期间再次编辑、快速切换请求、重新读档和退出排空。自动图形测量构建真实网格/碰撞并保存截图；完整人工游戏验收仍未完成。

## 执行方式

先使用当前项目的 Godot 工具流程让新增 class_name 脚本完成导入/解析。已有编辑器打开时使用该编辑器的刷新，不启动第二个编辑器。驱动器不会隐式执行编辑器导入，也不会重建缓存。

仅打印计划，不调用引擎、不创建实验输出：

```powershell
python tools/run_world_suite.py
```

先正确性，再数据层和图形：

```powershell
python tools/run_world_suite.py --run --stage correctness
python tools/run_world_suite.py --run --stage all --budget-minutes 150
```

all 包含正确性；若已单独运行且代码没有变化，可以分别使用 data/files/graphics 避免重复正确性检查。引擎由项目工具链发现，或通过 --engine 指定；执行时检查 4.7.stable。

单独自然地图图形对照：

```powershell
python tools/run_world_suite.py --run --stage graphics --layout 0 --repeats 2 --seconds 30
```

本轮正式图形比较使用较慢的固定路线，命令如下：

```powershell
python tools/run_world_suite.py --run --stage graphics --repeats 2 --seconds 20 --travel-seconds 60 --route-distance 512 --teleport-x 896 --budget-minutes 125
```

--travel-seconds 指定探索和返回各自时长，默认与 --seconds 相同；--route-distance 是单程 X 距离（默认 1024），--teleport-x 是传送目标 X（默认 2112）。本轮 512 格/60 秒约为 8.53 格/秒，X=896 对应受控布局的海洋。

--horizontal/--vertical 必须是 16 的正倍数；--workers 为 1..8。--candidates 接受 JSON 数组，例如 [[0,1,0,1],[1,1,1,1]]，列顺序 G/B/S/F。没有自动选择最终方案。

默认矩阵：G×B 的 9 组、B×S 的 15 组、三个编码×F 的 6 组、8 个图形代表组合；默认两轮。图形每个组合先 fresh，再新进程 restart，后者复用前者世界。每个图形进程依次 initial/stationary/explore/return/teleport/edit/drain；五个定时阶段默认各 30 秒。数据层前 8 段标为热身，汇总排除，但保留原始记录。

预算默认 150 分钟，执行上限夹在 180 分钟以内；超时终止当前自有进程，剩余项目标记未运行。默认约 32 个图形进程，实际能否跑完取决于首次生成速度；不会为凑齐矩阵超出预算。正确性失败后停止后续矩阵。

## 输出与解释

所有生成日志和实验存档位于 tmp/world_lab/<时间>/，不会提交。每个世界只用于对应组合与重复轮次，restart 单独标识。不要把新进程读取当成冷盘，系统缓存未受控；数据层紧接保存后的读取明确标记为暖缓存。

输出包括：suite_manifest.json（引擎、源码 SHA-256、机器与参数）、execution.json、各运行 manifest.json、frames.csv、tasks.jsonl、process_memory.csv、data.json、summary.csv、task_summary.json、data_summary.json、file_sizes.json、frame_time.svg、固定视角截图和 report.md。

逐帧：时间、阶段、驻留/脏/缺失段、在途任务、引擎静态内存、CPU process/physics 时间、draw calls。Windows 外部采样另记真实工作集/私有内存，不能与引擎静态内存混为一谈。GPU 时间标记 unavailable，不制造 GPU 数值。

逐任务：请求等待、采样、填充、导入、缓存命中、快照、磁盘 ID 映射、编码、压缩、校验、I/O 锁等待、写入/flush/提交校验、读取、解压、解包、网格构建、主线程提交、碰撞提交和请求到可见时间。read_us 包括打开/定位与封装校验；write_commit_us 是包含文件管理的总值，子阶段不能与总值重复相加。并行任务的耗时总和不等于玩家等待时间。

报告列出平均 FPS、P50/P95/P99 帧时间、超过 16.7/33.3/50ms 的帧数、积压峰值及各阶段耗时分布。曲线用桶最大值保留长帧。截图和遥测也存在开销；正式比较需保持配置一致，并结合原始帧与阶段边界分析。

最终选型由用户人工决定；性能数据见本轮测试报告，不自动切换主游戏方案。

遥测每约 2 秒转交独立后台批次追加写入，超时保留已经提交的批次；最后一个在途批次可能丢失。遥测写入同样消耗 CPU/I/O。正常关闭窗口先停止新请求并排空保存；外部超时强杀仅保留此前成功提交的数据。

存储日志还记录实际读取字节、保存回读字节、区域记录写入字节与索引提交字节；execution.json 记录每次进程结束时对应世界的磁盘大小。
