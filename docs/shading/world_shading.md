# 主世界光影接入

主入口仍为 `game/core/main.tscn`。`native_world.gd` 装配场景局部的 `AstraeonWorldShading`，不创建 autoload，也不依赖 test 目录。F6 打开/关闭分类设置菜单；菜单打开时暂停玩家输入，世界仍继续运行。偏好继续写入 `user://settings.cfg` 的 shading 节，当前格式为 `astraeon-shading-20260926-underwater`。主场景可导出指定 shading_profile 和 shading_settings_path。

## 数据与生命周期

- world 的 VoxelData 保留唯一权威体素数据。C++ 后台按 16³ section 复制带版本的只读输入，已移除整片 capture_shading_snapshot 与生产整片光场求解器。
- shading/native/cache 的 AstraeonSectionCache 复用 Voxel Tools 工作线程池，按 section 增量计算天空光、单色方块光、天气柱和静态灯索引。未知区段作为遮挡；完整高度依赖仍为 [-64,192)。
- 人物而非摄像机决定圆形驻留需求。原生编辑入口通知 section 失效；相机纯转向、日月流动不会重算体素光照。
- GPU 分页更新保留上一版有效光照；新网格等页就绪才显示。世界、网格与光照共用 2ms 主线程提交软预算。RD 上传由渲染线程执行，场景变更仍在主线程。
- 配置、内存口径、版本保护、天气持久驻留及性能验证见 [地图与光照缓存](../world/world_cache.md)。

## 已接入的效果

| 功能 | 主世界接入 |
| --- | --- |
| 天空、日月、昼夜与配色 | 程序化/纹理、圆/方形共用原参数 |
| 太阳/月亮阴影 | 距离、偏移、硬/软、分辨率、采样；硬阴影中性倍率 1 |
| 原生方块表面 | 六面图集、裁剪透明、常量自发光、原生网格 AO、金属/粗糙度和天空反射 |
| 环境光 | 原生天空传播、平滑采样、最低环境光、曲线和强度 |
| 静态与移动光源 | 5 种局部照明方案，实时灯使用全局预算池，手持灯绑定正式摄像机 |
| 水体 | 原生水方块网格、深度吸收/统一水色、波纹、天空反射、SSR/平面反射、按真实水体判断水下 |
| 云、植被与天气 | 方块云及云影、裁剪叶片风动/透光、降雨与派生屋顶高度图、湿润 |
| 相机 | FXAA/TAA、SSAO、屏幕光束/体积雾、自动曝光、景深、运动模糊、色差、Glow |
| 彩色阴影 | 接收方已覆盖方块/水；场景透明物件调用 register_transparent_caster/unregister_transparent_caster |
| 设置与显示 | F6 分类菜单、恢复默认、保存重载、FPS 与限帧 |

方块表面发光颜色来自静态外观资源，倍率来自光影配置；不再用测试灯颜色覆盖全部正式资源。实时灯颜色、能量、偏移和衰减来自 BlockLightAppearance；能量乘全局 local_light_energy，范围乘 local_light_range / 8。朝向作用于光源偏移。单色传播强度由静态 light_emission 决定，与表面自发光及实时灯请求独立。全局粗糙度乘已编译的各面粗糙度；金属度设置在已编译值之上向 1 混合。

水面复用原生网格，不再创建固定测试水池。当前生成器水位为 y=32（半开填充区间，不是 33），平面反射仅适用于这一共同水位。水下由摄像机所在体素是否为水决定。

## 边界与后续优化

- 当前完整接入的是已存在效果，不扩展方块外观编译器原本不支持的 normal/ORM/emission 贴图或混合透明方块。彩色阴影支持注册的 StandardMaterial3D 场景物件；当前原生目录没有玻璃方块，未创建一节点一体素的玻璃替代实现。
- 平面反射仍是单一水平面，不支持不同高度水池/瀑布的独立反射相机；SSR、天空反射仍可使用。水为生成静态水，不实现流体模拟。
- 派生光场已改为 section 增量求解和 GPU 单页上传；编辑后允许短暂异步延迟。性能结论必须同时包含延迟与队列收敛，不能只看平均 FPS。
- 天气柱按世界坐标缓存，移动窗口换原点保留仍驻留柱的湿润值；雨遮挡仍是单层地表高度近似，不是多层空间光追。
- 原生网格 AO 依赖 VoxelMesherBlocky 顶点数据。天空光也被用作方向光可见性约束，仍属于体素近似，不等同于完整 GI。
- 彩色阴影仍只有最近一层。静态灯池规模受 light_budget 限制，不创建无限量逐体素灯节点。已有发光石的 authored offset 在方块上方，避免点光源位于自身遮挡体内。

## 验证

### 帧时间 HUD

主场景沿用「显示 FPS」开关，使用 `game/ui/gdscript/frame_time_label.gd` 显示最近 10 秒的 FPS、1% Low、平均/P99/最长帧耗时，以及超过 16.67/33.33 ms 的帧数。FPS 为窗口总帧数除以总耗时；1% Low 为最慢 `ceil(N×1%)` 帧的平均耗时取倒数，不等同于 P99 的倒数。单个尖峰未必明显影响 P99，需同时看最长帧和慢帧数。

采样采用单调时钟记录真实 process 帧间隔，包含等待、限帧和调度影响，不是 GPU 执行时间或屏幕实际呈现时间。最近窗口的数据不足 2 秒或 100 帧时 Low 显示「采样中」。最多保留 32768 帧，极高帧率下窗口会短于 10 秒。固定环形缓存每帧追加，排序与文字刷新只每 0.25 秒进行；首次光照发布前不采样，隐藏 HUD 或窗口失焦后清空并重新采样。

`test/shading/gdscript/test_frame_time_label.gd` 验证已知慢帧数据、时间窗口淘汰、环形回绕、重置，以及一次主动注入的 80 ms 停顿。2026-09-23 Godot 4.7 / D3D12 图形验证失败数 0、退出 0，日志无脚本/渲染错误。注入测试期间均值仍为 188 FPS，而 1% Low 为 29 FPS、最长帧约 96 ms，证明 HUD 能揭示平均帧率掩盖的尖峰；这些数字不是游戏性能测量。

如果移动或转向时帧间隔稳定，但画面仍抖动，还需要独立检查物理插值、相机更新时序和显示同步。当前 HUD 不自动诊断这些原因。

### 昼夜更新路径

`_apply_lighting()` 只在初始化和设置变更时应用渲染质量、VSync、材质方案及模块配置。每帧时间推进走 `_update_daylight()`，仅更新日月方向/能量、天空/环境色、云影方向、水面天空色和雾色；天气权重变化另行更新云覆盖率及风力。时间推进不触发体素光场失效。

云配置只在设置变更时复制；平面反射保留同一个 Environment，与主视口共享 Sky，并独立保留线性 HDR、SSAO、体积雾和反射雾开关。昼夜不再每帧重建反射环境或重新设置水面 Shader。仍保留逐帧日月运动，没有降低阴影、天空反射质量或降低昼夜更新频率。

`test/shading/gdscript/test_day_cycle.gd` 提供固定视角的暂停/流动 ABBA 短测，并验证时间/太阳更新、云配置/网格稳定、反射环境复用、配置切换及天气独立更新。结果说明见 [昼夜性能修复](../../test/shading/reports/day_cycle_fix.md)。

`test/shading/gdscript/test_world_shading.gd` 使用 tmp 下隔离世界和配置，检查密闭空间、源删除、未知区段、负坐标、独立点光请求、主世界材质、光照发布、静态/手持灯、透明物件、三种水反射、水上/水下、跨区段和设置面板。运行使用 Godot 4.7 Forward+ / D3D12。截图中的瞬时 FPS 不作为性能基准。

测试结果及截图见 [主世界光影验收](../../test/shading/reports/world_shading.md)。
