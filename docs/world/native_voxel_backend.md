# C++ 体素底层决策

用户已明确选择：生产体素底层使用 C++，基于 Voxel Tools 二次开发；GDScript 体素实验不作为最终底层实现。本文件记录已批准的技术路线，不代表迁移或性能验收已完成。

## 职责

- C++／GDExtension：方块运行时数据、地形生成、流式加载与任务调度、网格与碰撞数据生成、存档编解码和 I/O 等体素基础设施。
- GDScript：玩法编排、UI、场景连接、配置和测试驱动。通过区域、批次和任务级接口与原生层交互，避免逐方块跨语言调用。
- 保留 16×16 区块列、16³ 段、水平圆形加载及独立垂直范围；保持权威方块数据与派生网格/碰撞分离。
- 工作线程不修改活动场景树，资源和场景提交遵循引擎线程约束。
- 先复用 Voxel Tools 的数据缓冲、网格器和任务系统，再针对实测高速移动瓶颈修改。前方预加载和项目保存契约需要单独实现、验证。

## 原型阶段兼容策略

**不保留任何向后兼容内容，只维护当前契约。**

- 不保留或新增旧接口别名、兼容适配层、历史行为分支、旧格式读取器、版本范围回退或迁移转换器。
- 修改接口、配置、资源或存档格式时，同步更新所有当前调用方、资源、测试和文档。
- 不支持的存档或配置格式明确报错，不自动猜测、转换或回退到旧格式。保留格式版本标识用于识别和拒绝不支持的版本。
- 当前格式内的校验、可恢复写入和损坏记录恢复属于数据可靠性要求，继续保留。
- 旧实验可保留为独立性能对照和历史证据，不接入生产代码作为兼容路径。

## 原生实现

- `AstraeonNativeGenerator` 直接填充原生 TYPE 通道，提供平原、森林、河流、海洋。ID 从正式数据状态表解析，使用草、泥土、树叶、竖直木头与水；其他木头轴向也纳入渲染和保存表。支持自然噪声与测试条带布局、可配置种子，世界高度 [-64,192)，海平面 32，仅支持 LOD0。
- 复用 `VoxelTerrain`、`VoxelMesherBlocky` 的原生存储、网格、碰撞与任务系统。不保留 GDScript 体素镜像；单次交互调用原生编辑接口。必要的原生保存快照仍存在。
- 默认水平圆形半径 64、垂直半径 32；可视与碰撞 viewer 分开，碰撞水平半径 32。出生点必须取得真实物理射线命中后才能移动。
- `AstraeonPrefetchViewer` 请求前方数据，不额外请求网格/碰撞。预测时间 0.75 秒、水平偏移上限 48；停止、反向及大于 128 体素的位移重置预测。世界属性 `prediction_enabled` 可开关比较。
- 保留上游过期任务取消；同优先级任务改为 FIFO，避免连续保存排序反转。世界、网格/碰撞与光照共用主线程提交软预算，默认 2ms；过期版本拒绝提交，等待较久的结果提升优先级。单个引擎调用仍可能超预算，峰值单独记录。
- 生成、读写计数和累计微秒通过 `get_metrics()` 获取。状态查询使用独立锁，避免主线程等待磁盘 I/O 锁；计数器使用原子变量。读写耗时包含方法中的锁等待和 I/O，不包含进入方法前的任务排队。

## 当前存档格式

游戏目录 `runtime_data/worlds/landscape_v2/`。每个 Region 覆盖 4×4×4 个 16³ 区段，文件名为负坐标安全的 `rx_ry_rz.avr`。128 字节头严格匹配格式版本 2、生成版本 2、种子、布局、状态数与有序状态表 SHA-256。元数据在 Region 第一次被访问时校验，不支持旧格式猜测、转换或回退。

每区段两条固定位置记录，各 8208 字节，包含序号、体素数、保留字段、8192 字节 little-endian UInt16 TYPE 数据与 CRC32。读取校验两条记录并选最新有效副本；写入较旧副本，fflush 与操作系统持久化调用成功后才记为完成。最新副本损坏可恢复上一完整记录；双副本均坏或头部损坏则明确报错，不允许重新生成覆盖玩家修改。

双副本和无压缩优先满足固定地址读取，文件较大。空槽可形成空洞，测试中的逻辑文件长度不等于实际磁盘分配量。首版每条记录独立落盘，有上限的 Region 句柄及已验证头部缓存、每 Region 串行锁已实现；尚无批量落盘或多进程同时写同一世界的支持。首次创建文件的头部未完整落盘时将拒绝读取；不能恢复一个从未完整创建的文件。

关闭窗口停止角色移动，等待流式与生成任务稳定空闲，再等待显式保存 tracker，并检查原生错误。失败或 60 秒超时留在游戏显示错误，不显示保存成功。编辑器的强制停止不等价于游戏窗口的正常关闭流程。

## 构建与验证

需要 Windows x64、MSVC C++ 工具链、Python、Godot 4.7 stable；SCons 固定为 4.10.1。无本机缓存时构建工具会通过 pip 安装到项目 tmp。

```powershell
python tools/build_native_voxel.py --target editor --install
python tools/build_native_voxel.py --target template_release --install
python test/native_world/runners/test_native_voxel.py --godot "F:/Godot_v4.7-stable_win64.exe/Godot_v4.7-stable_win64_console.exe"
```

构建并发、编辑器重启和进程处理统一遵循 [AGENTS.md 的 Godot 工具规则](../../AGENTS.md#godot-tooling-and-skills)。DLL 不入库，新检出先构建再打开编辑器。日志、源码和 DLL 指纹位于 `tmp/native-build/`。安装文件名带内容哈希，描述文件仅指向当前构建，不提供旧版本回退。

短测执行合约检查及四次图形运行：预加载关/开 × 新地图/重读，覆盖 16/32/64 体素每秒、直行、反向、转向、传送。输出 P50/P95/P99/最大帧时、近处网格与真实碰撞采样、任务队列峰值、生成/读写累计耗时和文件大小。结果在 `tmp/native-probe/`，归档见 [首版接入结果](../../test/native_world/reports/native_voxel_results_20260918.md)。

短测不替代持续压力测试、逐请求到可见延迟追踪、连续碰撞覆盖证明、断电测试或导出包验收。没有确定最终最优存储/预加载方案；旧基准参数不同，不能直接以 FPS 声称迁移收益倍数。

项目 C++ 已按功能放入 game/world/native；上游代码留在 native。构建清单从 game/*/native 生成。源码布局见 [目录说明](../core/source_layout.md)，开发规则见 [AGENTS](../../AGENTS.md)。测试统一位于 test/<测试项名称>/，原 tests 目录已迁移并删除。
