# 地图与光照缓存

生产入口为 `game/core/main.tscn`，场景局部 `AstraeonCacheCoordinator` 负责组装和数值配置。缓存热路径在 C++ 中，GDScript 只提交人物需求、切换设置及读取汇总；不建立第二份可编辑地图。

## 所有权与有效性

- world 的 `VoxelData` 是唯一权威体素数据。16³ section 的原生 revision 在创建、重新加载和编辑时变化；快照、网格及保存绑定此版本。世界实例独享 VoxelData 和光照 State，旧任务不能写入新世界。
- `VoxelTerrain.sections_changed` 批次通知包含 `world_instance`、`section`、`lifecycle`、`data_version`、变化的世界体素 `position/size` 和 `reason`（load/edit/release）。同一生命周期内的编辑递增数据版本，真正释放后重新加载会产生新生命周期；进入温缓存不发出释放事件。消费者拒绝其他世界和已经被替换的生命周期。
- 活跃 section 离开视距后留在原数据容器成为温缓存。保留环只延长已有数据驻留，不主动生成外围环。首次使用为候选，重复命中为保护段；优先淘汰越界、较旧、干净且无任务引用的候选。
- 未保存修改、活跃观察器引用及工作任务引用阻止淘汰。保存成功只确认同一 revision，旧保存不能清除新编辑。保存失败保留脏数据。
- 网格缓存使用本 section、26 个邻接 section 版本和材质编译依赖校验。释放绘制/活动碰撞实例后可保留 CPU 网格与碰撞数据；光照更新不重建几何。
- Region 使用有限的文件句柄和已校验头部缓存，同一 Region 串行，不同 Region 可并行。继续使用当前格式的双记录、CRC 与持久化确认，没有更改存档格式或自动删除旧存档。

## 光照与天气

`game/shading/native/cache/section_light_cache.h` 保存 section 的通透性、天空光、单色方块光、竖直直射光、六面边界版本及静态光源索引。独立增亮/减光队列按受影响 section 重新松弛，边界不变即停止扩散。全实心和无遮光的全天空区段有数学等价的常值快速路径。

人物位置决定需求，相机转向及昼夜参数不触发求解。天空光数据依赖覆盖当前世界完整高度 `[-64,192)`，水平另加一个 section；未知数据作为遮挡。后台逐 section 复制后立即释放空间锁，读取、传播、打包交错执行。工作任务复用 Voxel Tools 线程池，每个世界同一时刻只有一个传播任务。

每片最多 4096 次访问或约 2ms；单个快照、列高度计算及容器整理属于不可中断工作，峰值另外记录。完成页携带数据和六邻接版本，提交前校验；过期结果丢弃并合并重排。已可见几何保留旧有效光照，新几何等待有效页映射。

GPU 使用四组 Texture2DArrayRD。逻辑页仍为 **16×256 RGBA8 / 16 KiB**；为避免 D3D12 大量数组子资源的 CPU 开销，**默认容量下 256 个逻辑页横向放在一个 4096×256 数组层中**（每组仅 2/4/8 层；自定义容量选择能整除页数的 16–256 个页，不超分配预算）。单页通过渲染线程的 staging texture + texture_copy 更新，不上传整层或重建整池。32/64/128 MiB 分别容纳 2048/4096/8192 个逻辑页，常值页可共享。世界坐标页表保持显式有效性；先撤销映射再回收，上传后发布新映射。跨 section 平滑采样继续使用墙体遮挡约束。

上传时只激活本批新就绪页面；材质绑定只在页表范围、资源或容量改变时更新，普通像素上传复用绑定。周期性的内存统计/淘汰不单独改变光照就绪状态；若淘汰确实影响邻接光照，则相应传播仍参与就绪判定。

天气按世界 x/z 柱保存屋顶高度与湿润值。结构变化更新对应柱；人物移动只改变页表，不清空仍驻留柱的湿润值。GPU 天气页与光照共用提交预算。静态灯请求来自 section 索引，表面自发光、传播亮度、实时灯预算彼此独立。

## 数值配置与预算

`user://settings.cfg` 的独立 `cache` 节使用 `format=1`，拒绝其他格式。F6 设置内的缓存面板提供数值输入；任一数值改变即显示自定义。

GPU 光照容量可按整数 MiB 在 1–128 之间自定义（包括 96MiB），三个预设只负责填写数值。极小容量可能不足以覆盖可见内容，此时显示容量压力并等待有效页面，不能把缺失几何带来的高 FPS 当作性能收益。

| 参数 | 节省 | 均衡（默认） | 大缓存 |
|---|---:|---:|---:|
| CPU 管理缓存 MiB | 256 | 512 | 1024 |
| GPU 光照 MiB | 32 | 64 | 128 |
| 数据保留环 m | 16 | 32 | 64 |
| CPU 网格保留秒数 | 5 | 15 | 30 |
| Region 句柄数 | 16 | 32 | 64 |

共同默认：主线程总提交软预算 2ms，其中光照上传 0.75ms、2MiB/帧；传播工作片 4096 次访问 / 2ms；预测 0.75 秒，前向最多 48m；CPU 预算预留 10% 给任务及待提交结果。共享提交预算覆盖原生世界结果、网格/碰撞提交与光照上传，不能中断单次引擎调用。结果按原优先级排序，等待 250ms 的结果提升优先级。

CPU 网格过期检查采用轮转队列，每帧最多 32 条或约 100μs，并计入共用预算。地图载荷统计与淘汰在后台续排，不把全部区段的检查放入单次工作片。元数据枚举、排序和单个引擎调用仍是软预算，`peak_slice_usec`、`single_task_peak_usec/name` 用于定位实际超时项。

占用统计是受管理的 CPU 数据/数组有效载荷，包含体素、光照、天气、派生网格和已跟踪的待提交数据；不等于进程私有内存，未包括驱动资源、分配器元数据和引擎内部缓存。任务数量与已知网格临时字节双重限制入队。预算不足先回收非活跃缓存、暂停额外预测；不可淘汰数据超预算显示压力，不降低用户视距、不丢修改。

GPU 预算切换在显式暂停/加载阶段重建；恢复完成后保存设置，超时返回错误。容量不足不覆盖附近有效页，保留待提交结果，并等待释放容量；HUD 的压力与队列指标必须一起观察。

上传等待队列有 128 页上限；近处结果可以替换等待中的远处结果，远处结果回到待发布集合。无法分配槽位的页轮转等待，避免阻塞已有页面的编辑更新。常值共享页有引用计数，最后一个映射解除后才回收槽位。`capacity_pressure` 是累计次数，`capacity_blocked` 是当前状态；HUD 使用后者，恢复后会解除警告。上传字节限制必须足以容纳一页和两次页表提交，界面会拒绝无法推进的值。

`native_voxel_pool_used_bytes/reserved_bytes` 单独报告原生全局体素内存池的使用/保留容量，它们与受管理载荷有重叠，不能直接相加。缓存统计随后台检查刷新，初始化期间未完成的统计不能解释为占用为零。GPU 天气页另占 4MiB；GPU 光照预算不包含天气、页表、暂存纹理及驱动开销。

## 验证与复现

- `python test/shading/runners/run_cache_native.py`：独立 C++ 求解器与全量 BFS 对比，随机和 128 方块编辑、跨边界、负坐标、光源删除、未知数据。
- Godot 图形运行 `res://test/shading/gdscript/cache_contracts.gd`：真实主世界编辑、GPU 读回、温缓存返回、保存期间编辑、配置及 32/64/128MiB 切换。
- `res://test/shading/gdscript/cache_pressure.gd`：故意使用 64MiB CPU / 32MiB GPU 和 480m 需求制造压力，检查保存修改、等待上限及缩回 64m 后恢复。此项不是视距性能验收。
- 同一压力脚本添加 `-- --large` 使用大缓存预设和 960m 人为需求；只验证容量耗尽与恢复，不构成 960m 性能或正常玩法承诺。
- `res://test/shading/gdscript/cache_lifetime.gd`：反复创建和销毁世界，检查原生引用、任务排空及 GPU 纹理占用释放；原生内存池保留容量与正在使用的体素内存分别记录。
- `res://test/shading/gdscript/cache_ui.gd`：真实 F6 缓存面板的 1080p、1440p、4K、超宽屏渲染与边界检查。
- `res://test/shading/gdscript/cache_edit_latency.gd`：64/256 视距的近处放置/删除，分别观察 GPU 光照读回和实际点光源节点，50ms GPU 轮询区间给出可见延迟上界。读回会同步 GPU，本测试不用于 FPS 比较。
- `python test/shading/runners/run_cache_suite.py --run`：1080p、64/256、旧/新 ABBA 两轮，静止、纯转向、区段内/边界绕转、8/22/40m/s、折返、连续跨区段及传送。旧版工程仅隔离保留在 tmp，绝不作为生产回退路径。
- 所有生成世界、原始帧、显卡遥测、引擎日志位于 tmp；人工整理的结论与截图位于 `test/shading/reports/`。旧对照所用源码/二进制指纹应随结果保存。

性能验收同时检查中位帧耗时、1% Low、P99/最大帧、光照慢帧、发布数量、更新延迟及停止后收敛。新几何尚未就绪时的高 FPS 不能视为性能通过。首次管线编译必须标注，不能从最大帧指标中隐去。本轮验收范围是当前 256m 世界高度，不外推到最终 512m 高度或所有光影组合。

本轮实现、1080p 对照、容量与资源释放结果见 [2026-09-24 验收报告](../../test/shading/reports/cache_20260924.md)。天气等待队列满载时保留待发布状态，不得丢弃结果并伪报收敛。
