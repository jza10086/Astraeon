# 项目本地数据目录

项目路径统一由 `game/core/gdscript/project_paths.gd` 解析。开发时使用工程根目录，桌面导出后使用可执行文件同级目录；不依赖工作目录，不将业务文件写入系统用户目录，写入失败不切换目录。

| 目录 | 内容 |
| --- | --- |
| external_data/characters/ | 外部人物 GLB，打开人物页时扫描 |
| external_data/blocks/ | 外部 .aebpack 内容包，主菜单安装／选择 |
| runtime_data/settings.cfg | 画面、缓存、人物、世界和内容包选择 |
| runtime_data/worlds/<名称>/ | 世界数据、元数据、物品栏及派生缓存 |
| runtime_data/logs/ | 应用文件日志 |
| tmp/ | 测试与一次性工具输出 |

外部导入和运行时目录各有 .gdignore，防止编辑器扫描、自动导入或打包本地数据。Git 仅保留目录骨架；内置资产仍属于 game/。所有项目新功能遵守根 AGENTS.md 的存储规范。

本次只调整路径，不修改任何数据格式。已有游戏业务文件进行一次性原样复制，原件保留；生产代码不包含旧目录扫描、转换或兼容路径。旧格式数据仍按各模块规则拒绝读取。已在运行的游戏需要重新启动，才能使用新默认路径。

## 工具边界

上述规范覆盖项目编写的游戏与测试文件。Godot 编辑器的全局偏好、引擎驱动缓存，以及 MCP 插件的注册／鉴权文件属于第三方工具自身存储；本次没有修改全局引擎安装或插件存储协议，不能将此变更宣称为整个 Godot 进程零系统用户目录写入。Godot 默认数据路径依据见 [官方说明](https://docs.godotengine.org/en/latest/tutorials/io/data_paths.html)。项目应用日志已显式指定项目内路径；导出启动器若需文件日志，应传入安装目录下日志文件的绝对路径。
