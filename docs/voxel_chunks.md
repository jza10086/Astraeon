# 区块与加载范围约定

状态：单位、区块与加载约定已批准；2026-09-22 加入已批准的方块材质设计，材质 Resource 结构已实现，原生渲染接入待完成。主游戏已接入原生世界；下文基准实现与复现部分为历史评估记录，当前生产状态见 [项目结构](project_structure.md)。

## 单位和坐标

- 体素（voxel）：一个方块的数据单元。项目标准方块边长为 1 Godot 单位 = 1 米；材质定义不改变方块占据的体素尺寸。
- 区块（chunk）：XZ水平面上 **16×16体素的区块列**。区块坐标为 `(cx, cz)`，不把高度写入区块尺寸。
- 区块段（section）：区块列内 **16×16×16体素**的垂直分段，坐标为 `(cx, sy, cz)`。当前插件的数据块和网格块均采用这个尺寸；它们是实现术语，不等同于整根区块列。
- 当前评估世界Y∈[-128,384)，共512层；每列32段，段坐标sy∈[-8,24)。这是基准范围，不是已承诺的最终世界限制。
- `cx=floor(x/16)`，`cz=floor(z/16)`，`sy=floor(y/16)`；局部坐标为世界整数坐标减去段坐标乘16，始终落在0～15。必须向负无穷取整：x=-1→cx=-1、局部15；x=-16→cx=-1、局部0；x=-17→cx=-2、局部15。
- 区块覆盖采用半开区间：[16cx,16(cx+1))×[16cz,16(cz+1))，不重叠、不留缝。

## 方块属性与材质契约

2026-09-22 批准。三个材质 Resource、校验、六面/UV/法线变换及示例已实现，静态方块定义已增加 appearance 引用；尚未接入原生世界的材质编译和渲染。原生世界仍使用 game/world/resources/block_library.tres。

### 所有权与资源结构

方块属性分为三部分：静态逻辑属性（ID、特性、挖掘耗时等）、动态逻辑属性（挖掘进度、坐标、当前朝向等）与材质属性。本节只设计材质部分；前两类由 data、world、gameplay 等负责模块定义，shading 不复制权威状态。

材质部分称为“方块外观定义”，覆盖六面外观、标准朝向及照明描述，由 game/shading 拥有。采用三个共享、只读的 Resource：

| 资源 | 职责 |
| --- | --- |
| BlockAppearance | 外观入口，保存默认及六面表面材质、标准朝向、可选光源描述 |
| BlockSurface | 表面贴图、颜色、透明、光泽及自发光 |
| BlockLightAppearance | 向周围照明的颜色、强度、范围及局部位置 |

上表为概念名；实现时共享 class_name 使用 Astraeon 前缀。类型归入 game/shading/blocks/gdscript，配套资源与着色器归入该功能的 resources/、shaders/，测试归入 test/shader；实现时按需创建，不预建空目录。静态方块定义引用外观资源；多个方块可共享外观，多个面可共享表面资源。资源引用不允许反向持有世界或玩法实例。

### 表面属性：BlockSurface

| 字段 | 含义与默认约定 |
| --- | --- |
| base_color | 基础颜色及透明度，默认白色、不透明 |
| albedo_texture | 可选颜色贴图；缺省为白色，与 base_color 相乘 |
| normal_texture / normal_strength | 可选法线贴图及强度；默认无贴图、强度 1 |
| roughness / metallic / specular | 粗糙度、金属度、非金属高光，默认 1 / 0 / 0.5 |
| orm_texture | 可选合并贴图，R 为材质 AO、G 为粗糙度、B 为金属度；缺省各通道为 1，G/B 分别乘对应标量 |
| alpha_mode | 不透明、裁剪透明、混合透明，默认不透明 |
| alpha_cutoff | 裁剪阈值，默认 0.5，仅裁剪模式有效 |
| emission_color | 普通颜色值，默认白色；不另设颜色 I 强度 |
| emission_energy | 表面自发光倍率，默认 0，即关闭 |
| emission_texture | 可选自发光颜色与区域贴图，缺省为白色 |
| double_sided | 是否显示背面，默认关闭 |

自发光结果 = 发光贴图 × 发光颜色 × 发光倍率。发光倍率只控制表面自发光，不自动产生周围照明。颜色贴图按颜色数据处理；法线、ORM 按线性数据处理。材质 AO 与已有顶点 AO 分开，全局顶点 AO 设置仍独立生效。

水体的波纹、深度吸收、反射继续使用专用水材质，不混入普通方块表面字段。材质透明度只描述视觉；逻辑透光、碰撞及游戏规则使用的光照等级由其他模块显式定义，不从 alpha_mode 自动推断。

### 六面与方向：BlockAppearance

| 字段 | 含义 |
| --- | --- |
| default_surface | 六面的默认表面材质，必须提供 |
| face_surfaces | 上、下、前、后、左、右的可选覆盖；未提供时使用默认材质 |
| face_uv_rotations | 每面 UV 旋转，限定 0/90/180/270 度，默认 0 |
| face_uv_mirrors | 每面 U/V 镜像，默认关闭 |
| authoring_orientation | 素材标准朝向到规范朝向的固定旋转，默认恒等；方块首版限保持轴对齐的立方体旋转 |
| light | 可选 BlockLightAppearance，缺省不向周围照明 |

方块规范方向为上 +Y、前 -Z、右 +X；后 +Z、左 -X、下 -Y。该方向约定针对方块，不改写角色模型的独立资产方向契约。局部位置以方块中心为原点，单位为米；一个标准方块各轴边界为 -0.5 到 +0.5。

标准朝向是素材的固定属性；当前朝向是实例动态逻辑属性，由其他模块传入。变换顺序为素材方向修正，再应用当前放置方向。六面材质映射、贴图方向、法线、光源局部位置使用一致的变换。实现时需固定各面的 UV 切线约定并验证镜像后的法线方向。

例：原木上下端面使用年轮、侧面使用树皮；横放时旋转整个外观，不额外维护一套横放贴图。

### 周围照明：BlockLightAppearance

| 字段 | 含义与默认约定 |
| --- | --- |
| color | 照明颜色，默认白色 |
| energy | 照明强度，默认 0，即关闭；不直接等同于流明或体素 0–15 光照等级 |
| range | 影响距离，单位米；启用时必须为正 |
| attenuation | 距离衰减参数，由选定照明方案明确解释 |
| local_offset | 相对方块中心的局部偏移，单位米，默认零 |
| source_radius | 发光体尺寸参数，单位米，供支持的软阴影方案使用，默认 0 |
| shadow_policy | 跟随全局设置或不投射阴影，默认跟随全局 |

表面自发光和周围照明独立：普通石头两者均无；发光纹理可仅自发光；灯可同时具有两者；辅助照明可仅照亮周围。

资源不固定选择实时点光源、体素传播或其他照明方案。方案、实时灯数量、阴影预算由光影配置及光源预算系统管理；各方案须说明字段支持情况、强度映射和无效参数，不能假定效果等价。光源数据不授权 shading 持有另一份权威体素状态。

### 运行时接口与性能约束

其他模块提供外观引用、位置、当前朝向、必要的动态外观参数（例如灯开关或发光倍率）及变化通知。基础资源保持只读；实例熄灯应使用实例参数或切换外观，不修改共享资源。挖掘裂纹和选中描边作为动态覆盖效果，不属于基础材质。

加载时把共享外观整理为渲染使用的索引及贴图集合；不为每个方块复制 Resource、创建独立 Material 或灯节点。保持区段网格批量生成，六面不同材质不强制拆成六个绘制批次；图集或贴图数组的选择留给实际实现。大量发光方块仍可只显示自发光，实时照明继续受预算管理。

首版范围为六面外观、方向映射、透明模式、基础光泽、自发光与独立光源描述。贴图动画及更多特殊材质按实际需求加入。接入验收需覆盖六面方向与旋转、共享资源不被实例修改、自发光与周围照明独立、透明模式和不同照明方案的字段有效性；资源层测试已通过 360 项检查，含全部 24 种立方体旋转、UV 镜像切线、共享引用和保存重载；渲染接入后的视觉与性能验收尚未进行。

## 加载契约

视距指**水平半径**，不是直径或区块总数。256体素 = 16区块半径，直径约512体素。

加载中心随观察者移动，并向下对齐到16体素网格。以该锚点为圆心，区块水平中心 `(16cx+8,16cz+8)` 与锚点的距离不超过半径时选择该区块列。因此锚点在区块边界交点；观察者与锚点在X、Z各轴上均有小于16体素的量化偏差。采用整区块显示，边缘仍呈阶梯形。

令观察者所在区块为 `(ax,az)`、区块半径为r，精确判定为：

`(2(cx-ax)+1)^2 + (2(cz-az)+1)^2 <= (2r)^2`

r=16时选择812个水平区块列；原盒形为1024列，减少20.70%。这是离散几何覆盖差异，不能直接换算为FPS提升。

垂直半径独立设置为 `vertical_distance`。本轮保持256体素（上下各16段），按段对齐后裁剪到世界Y边界；**不强制加载整列512层**。相机Y提高时，实际加载的上下段范围随之变化。水平和垂直半径均要求16的整数倍。

网格和碰撞使用同一个圆形范围。体素数据额外保留一段邻居边框，包括斜向邻居，以保证边缘网格完整；因此数据段数大于可网格化段数，空段也不一定生成可绘制网格。

现阶段保留插件任务调度，仅替换选择范围。没有加入额外卸载缓冲、朝向预测或独立碰撞半径；这些改变应另行测量。

## 实现与复现

基于Voxel Tools 1.7.0，源码75d3c6d996ed2331c80edcd8c3ebc947afc0f041；本地补丁为 tools/voxel_patches/horizontal_circle.patch。

使用 `python tools/build_voxel_circular.py --install` 重建并安装本机Windows编辑器扩展。只给基准启用 `horizontal_circular_loading`，默认关闭，不改变上游示例。圆形模式限定数据/网格均为16体素，必须在添加观察者之前配置。

运行 `python tools/run_voxel_suite.py --run --driver d3d12` 执行256体素矩阵，计时上限30分钟；编译准备单独计时。实际渲染1920×1080，窗口1280×720。历史盒形结果保留，不能覆盖或当成当前圆形结果。

当前本地构建只覆盖Windows x86_64编辑器DLL；导出用的template_debug/template_release仍为上游发行文件。后续需要导出圆形加载版本时，应先对相应模板构建应用同一补丁。原DLL按SHA-256命名备份在tmp/voxel-circular-build下。

针对性验证入口：`godot --headless --path benchmarks/voxelgame/project --script res://astraeon_benchmark/test_circular_loading.gd`（使用项目指定Godot 4.7）。实际原生数据集合与独立的圆盘加邻居集合逐段比较；覆盖负坐标、垂直移动、远距传送、上下边界、半径改变、碰撞标志切换及观察者移除。该检查不代替图形性能矩阵。

实现入口：game/shading/blocks/gdscript；示例为同功能 resources/ 下的 stone.tres、lamp.tres、log.tres。校验调用 validate()，返回带字段上下文的错误列表，不修改或静默修正资源。字典键使用 Face 枚举 TOP/BOTTOM/FRONT/BACK/LEFT/RIGHT（0–5）；未覆盖的面使用 default_surface。UV 先镜像后绕中心旋转，面切线满足 U×V=外法线，法线贴图解码后的向量通过 face_tangent_basis() 变换；向量的绿色通道转换由具体贴图导入契约负责。
