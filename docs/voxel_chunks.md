# 区块与加载范围约定

状态：已批准；圆形加载先在 benchmarks/voxelgame 独立评估工程实现，主游戏仍为占位场景。

## 单位和坐标

- 体素（voxel）：一个方块的数据单元。本轮基准中边长1 Godot单位，按1米解释。
- 区块（chunk）：XZ水平面上 **16×16体素的区块列**。区块坐标为 `(cx, cz)`，不把高度写入区块尺寸。
- 区块段（section）：区块列内 **16×16×16体素**的垂直分段，坐标为 `(cx, sy, cz)`。当前插件的数据块和网格块均采用这个尺寸；它们是实现术语，不等同于整根区块列。
- 当前评估世界Y∈[-128,384)，共512层；每列32段，段坐标sy∈[-8,24)。这是基准范围，不是已承诺的最终世界限制。
- `cx=floor(x/16)`，`cz=floor(z/16)`，`sy=floor(y/16)`；局部坐标为世界整数坐标减去段坐标乘16，始终落在0～15。必须向负无穷取整：x=-1→cx=-1、局部15；x=-16→cx=-1、局部0；x=-17→cx=-2、局部15。
- 区块覆盖采用半开区间：[16cx,16(cx+1))×[16cz,16(cz+1))，不重叠、不留缝。

## 加载契约

视距指**水平半径**，不是直径或区块总数。256体素 = 16区块半径，直径约512体素。

加载中心随观察者移动，并向下对齐到16体素网格。以该锚点为圆心，区块水平中心 `(16cx+8,16cz+8)` 与锚点的距离不超过半径时选择该区块列。因此锚点在区块边界交点；观察者与锚点在X、Z各轴上均有小于16体素的量化偏差。采用整区块显示，边缘仍呈阶梯形。

令观察者所在区块为 `(ax,az)`、区块半径为r，精确判定为：

`(2(cx-ax)+1)^2 + (2(cz-az)+1)^2 <= (2r)^2`

r=16时选择812个水平区块列；原盒形为1024列，减少20.70%。这是离散几何覆盖差异，不能直接换算为FPS提升。

垂直半径独立设置为 `vertical_distance`。本轮保持256体素（上下各16段），按段对齐后裁剪到世界Y边界；**不强制加载整列512层**。相机Y提高时，实际加载的上下段范围随之变化。水平和垂直半径均要求16的整数倍。

网格和碰撞使用同一个圆形范围。体素数据额外保留一段邻居边框，包括斜向邻居，以保证边缘网格完整；因此数据段数大于可网格化段数，空段也不一定生成可绘制网格。

现阶段保留插件任务调度，仅替换选择范围。没有加入额外卸载缓冲、朝向预测或独立碰撞半径；这些改变应另行测量。

## 实现与复现

基于Voxel Tools 1.7.0，源码75d3c6d996ed2331c80edcd8c3ebc947afc0f041；本地补丁为 tools/voxel_patches/horizontal_circle.patch。

使用 `python tools/build_voxel_circular.py --install` 重建并安装本机Windows编辑器扩展。只给基准启用 `horizontal_circular_loading`，默认关闭，不改变上游示例。圆形模式限定数据/网格均为16体素，必须在添加观察者之前配置。

运行 `python tools/run_voxel_suite.py --run --driver d3d12` 执行256体素矩阵，计时上限30分钟；编译准备单独计时。实际渲染1920×1080，窗口1280×720。历史盒形结果保留，不能覆盖或当成当前圆形结果。

当前本地构建只覆盖Windows x86_64编辑器DLL；导出用的template_debug/template_release仍为上游发行文件。后续需要导出圆形加载版本时，应先对相应模板构建应用同一补丁。原DLL按SHA-256命名备份在tmp/voxel-circular-build下。

针对性验证入口：`godot --headless --path benchmarks/voxelgame/project --script res://astraeon_benchmark/test_circular_loading.gd`（使用项目指定Godot 4.7）。实际原生数据集合与独立的圆盘加邻居集合逐段比较；覆盖负坐标、垂直移动、远距传送、上下边界、半径改变、碰撞标志切换及观察者移除。该检查不代替图形性能矩阵。
